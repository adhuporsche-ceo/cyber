# Slide 1: Title

## NETPROBE

### Automated Network and Website Vulnerability Assessment Tool

NETPROBE is a modular defensive security tool that discovers exposed services and websites, identifies technologies and versions, detects security weaknesses, correlates potential vulnerabilities, calculates risk, and generates evidence-based reports.

# Slide 2: Problem Statement

Organizations often expose network services and websites without having a centralized understanding of their security weaknesses.

Manual security checking of the following is time-consuming and inconsistent:

- Open ports
- Running services
- Service banners and versions
- HTTP security headers
- HTTPS and TLS configuration
- Cookie security attributes
- Publicly exposed administrative or configuration paths
- Potentially vulnerable software versions

Security teams need a fast, repeatable, and explainable assessment process that converts raw scan data into actionable security findings.

---

# Slide 3: Proposed Solution

NETPROBE automates the security assessment workflow for authorized targets.

It performs:

- Host and port discovery
- Service and protocol detection
- Banner collection
- Product and version fingerprinting
- Website security analysis
- TLS certificate checks
- Security rule evaluation
- Local vulnerability correlation
- Risk calculation
- Baseline and change detection
- TXT, JSON, CSV, and HTML reporting

NETPROBE is designed to discover and assess systems, not compromise them.

---

# Slide 4: Project Objectives

## Primary Objectives

1. Discover network exposure.
2. Identify open ports and services.
3. Detect products and software versions safely.
4. Analyze website and HTTPS security configuration.
5. Match detected versions with known vulnerability records.
6. Clearly distinguish potential vulnerabilities from confirmed exploitation.
7. Explain the evidence and confidence behind every finding.
8. Provide practical remediation guidance.
9. Track security changes through baselines.
10. Produce machine-readable and human-readable reports.

# Slide 7: Operating Modes

## Network Assessment

```powershell
python main.py network 192.168.1.10 --ports top100
```

Discovers:

- Reachable hosts
- Open TCP ports
- Services and protocols
- Banners
- Products and versions
- Network exposure findings

## Website Assessment

```powershell
python main.py web https://example.com --format html
```

Checks:

- HTTP status
- HTTPS availability
- HTTP to HTTPS behavior
- Security headers
- Cookies
- TLS certificate and expiry
- Server disclosure
- Directory listing indicators
- Sensitive public paths

## Vulnerability Assessment

```powershell
python main.py vuln example.com --ports 22,80,443 --format json
```

## Full Assessment

```powershell
python main.py assess example.com --ports 80,443 --format json
```

Combines network discovery with website assessment.

# Slide 16: Baseline and Change Detection

Create a baseline:

```powershell
python main.py baseline 192.168.1.10 --ports top100
```

Review scan history:

```powershell
python main.py history
```

NETPROBE can compare current results with a stored baseline to identify:

- New hosts
- New open ports
- Closed ports
- Service changes
- Version changes
- New vulnerabilities
- Vulnerabilities no longer detected

This supports remediation verification and continuous monitoring.

# Slide 19: Safety Boundary

NETPROBE is a defensive assessment tool.

## Allowed Behavior

- TCP connection scanning
- Safe banner collection
- HTTP GET and HEAD requests
- Header and cookie inspection
- TLS certificate inspection
- Version correlation
- Configuration assessment
- Baseline comparison

## Excluded Behavior

- Credential attacks
- Password cracking
- Exploit execution
- Malware
- Persistence
- Data destruction
- Unauthorized access

Every assessment must be performed only against authorized targets.

---

# Slide 20: Accuracy and False-Positive Control

NETPROBE prioritizes evidence quality over the number of findings.

```text
Evidence
   +
Confidence
   +
Correlation
   =
Finding Quality
```

Quality controls:

- Exact or normalized version matching
- Service-aware rule matching
- Evidence attached to findings
- Confidence level attached to detections
- Potential status for CVE matches
- No automatic exploit execution
- Duplicate findings avoided by stable IDs

Principle:

> Never confuse detection with proof.
